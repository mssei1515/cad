# ファイル操作

保存するデータは[保存形式](../data/保存形式.md)、不正データの拒否・無効状態保持は[読込と互換性](../data/読込と互換性.md)に従う。

## 1. 開く・保存・保存先

File System Access APIが利用できる環境では、開くと名前を付けて保存でそのpickerを表示し、`.jot2d`だけを対象とする。

`showOpenFilePicker`を持たない環境では、「開く」は自動的にHTML file inputを使用する。ブラウザ自動検証用URL parameterとして`filePicker=input`を指定した場合も同じ経路を使用する。

この互換経路で開いたDocumentには書込み可能なファイルハンドルがないため、現在の保存先を未設定にする。

開いたファイルまたは名前を付けて保存したファイルのハンドルは、次回の保存先としてsession中だけ保持する。

保存先をまだ持たないDocumentで「上書き保存」を実行した場合は名前を付けて保存と同じpickerを表示し、保存先を持つ場合はpickerを出さずに同じファイルへ上書きする。

pickerをキャンセルした場合は通常の操作中止として扱い、error表示、Document変更、現在の保存先変更を行わない。

ファイル内容は現行のDocument JSONをそのまま使用する。

`showSaveFilePicker`を持たず書込み可能な保存先ハンドルもない環境では、上書き保存／名前を付けて保存で現在のDocument名に`.jot2d`を付けたJSONをダウンロードする。既存ファイルを直接上書きせず、毎回ダウンロードする。UIは「ダウンロード開始済み」と表示し、ブラウザのダウンロード完了やOS側の保存結果を保証する表示は行わない。

## 1.1 未保存の変更とファイルの切り替え

Menu Bar右側にDocument名と「新規ドキュメント」「未保存の変更」「保存中…」「保存済み」「ダウンロード開始済み」「ブロック編集中」を表示する。未保存の変更またはBlock Editorがあるときはブラウザのタイトル先頭にも`●`を表示する。

起動直後の空Document、正常読込後、正常保存後を比較基準とし、編集履歴の現在のDocument内容が基準と異なるときに未保存とする。Undo／Redoで基準の内容に戻れば未保存表示も解除する。保存時刻、アクティブSketchの切り替え、Selection、hover、viewportの変更だけでは未保存にしない。ダウンロード経路ではダウンロード開始時の内容を比較基準にする。基準はsession内だけに保持し、Document JSONやUndo履歴に追加しない。

別ファイルを選択した後、未保存の変更がある場合に共通選択ダイアログで「保存して開く」「保存せずに開く」「キャンセル」を表示する。初期focusは「保存して開く」。Esc、×、キャンセルでは現在のDocument・履歴・保存先を維持する。「保存して開く」は保存が成功し、その保存中に追加編集がなかった場合だけ読込へ進む。保存キャンセル・保存失敗では切り替えない。ファイル選択自体のキャンセルでは未保存の確認を出さない。

正常に別ファイルを読み込んだときはUndo／Redo履歴をそのDocumentから開始し、以前のファイルへUndoで戻らない。Block Editor中は従来どおりファイルの開く・保存を拒否する。

未保存のDocument、Block Editor、保存処理中のページを閉じる・再読み込み・別ページへ移動する際は、ブラウザ標準の離脱確認を要求する。進行中の作図・ドラッグで履歴に未確定の変更も離脱時には比較する。確認文言と確認の表示条件はブラウザに従い、モバイルでの強制終了などすべての終了経路を保証しない。自動保存・復元機能ではない。

## 1.2 保存中の編集と失敗

書込み開始前にDocument JSONを1回取得し、その内容を書込み、streamのclose成功後に保存先と保存基準を更新する。書込み中に追加された編集は未保存として残す。書込みまたはcloseの失敗時は可能ならstreamをabortし、保存先・保存基準を変更しない。

保存処理中の重複保存・別ファイルを開く操作、読込・未保存確認中の別のファイル操作は開始しない。未保存確認の「保存して開く」からの保存だけを例外とする。

未保存確認後のファイル取得・読込待機中に現在の図面が変更された場合は、読込による置き換えを中止して追加編集を維持する。ネイティブpickerで同じ保存先を選び「保存して開く」を実行した場合は、保存後にファイルを取得し直して最新の内容を開く。

## 2. 保存先ハンドルの保持範囲

File System Access APIで取得した現在のファイルハンドルはapplication sessionだけで保持する実行時状態であり、Document JSON、Block Editor draft、Clipboard、Undo/Redo履歴には含めない。

## 3. 操作の入口

File menuとToolbarは同じ開く・上書き保存commandを使用する。上書き保存はCtrl+S、名前を付けて保存はCtrl+Shift+Sでも実行できる。画面配置は[UI・操作・履歴](../ui/画面構成.md)を参照する。

## 4. PNG出力

File menuの「PNG出力…」／「Export PNG…」から、通常の作図Canvasと既存コマンドパネルで出力操作を開始する。別dialog・専用preview・既存矩形4辺選択は設けない。出力対象は現在の編集scopeの表示中の図形・塗りつぶし・寸法・注記・参照画像で、Block／派生Instanceの表示内容も含む。背景は常に透過とし、図形は現在のthemeの通常色を使う。選択・hover・拘束状態・ID・編集ハンドル・作図preview・範囲枠は出力しない。明示Pointと補助線の外観は含む。

Canvas上で対角の2点を順にクリックし、水平・垂直の矩形を指定する。既存図形は不要。通常作図と同じ候補を10 CSS pxの許容距離で照会し、候補があればスナップしmarkerを表示、なければクリック位置を使う。1点目からpointerまでの範囲を仮表示し、幅・高さが正の2点目で確定する。確定後の再クリックは新しい1点目となる。「範囲をクリア」で再指定できる。指定範囲はmmの図面座標で保持し、パン・ズーム・ウィンドウサイズ変更では変化しない。Geometry・拘束・履歴・通常作図のactive snapは変更しない。

パネルには解像度（DPI）の数値入力、出力ピクセル数、背景透過の表示、範囲をクリア、キャンセル、PNGを保存を表示する。DPIは開始時300で、正の有限値へ変更できる。96dpiは現在のCanvasのCSS表示座標1pxをPNGの1pxに対応させ、192dpiは2倍、300dpiは3.125倍に対応する。devicePixelRatioには依存しない。画像幅・高さはそれぞれ`round(範囲のmm寸法 × 現在のviewport.scale × DPI / 96)`、最小1pxとする。範囲未確定・DPI不正・1辺16384px超または総画素33554432px超では保存を無効にする。

出力は現在の画面表示倍率・注記サイズ・線幅を基準とし、指定DPIに対応する倍率で描き直す。bitmapの単純な拡大は行わない。範囲を指定した後のズーム変更は出力ピクセル数と構図へ反映され、パンだけでは範囲とピクセル数は変わらない。現在のviewportを変更せずに描画し、描画完了・失敗時には元のCanvas bitmapへ同期的に復帰する。画像とfontの準備を待ち、decode失敗は通知する。

保存先pickerは通常のファイル保存として使用し、非対応環境ではダウンロードする。名前はDocument名＋`.png`。PNG出力はDocumentの保存先・保存基準・未保存状態・Undo/Redo・Selectionを変更しない。範囲とDPIはDocumentへ保存しない。Escまたはキャンセルで終了する。picker取消は範囲を保持して戻り、生成・書込み失敗はパネルに表示して再試行できる。書込み失敗時は可能ならstreamをabortする。保存中は重複出力・取消を抑止する。未確定作図またはDocumentファイル操作中は開始しない。
