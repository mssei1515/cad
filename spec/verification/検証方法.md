# 検証方法

保証範囲は[保証対応](保証対応.md)を参照する。以下は現在の[package.json](../../package.json)と[Playwright設定](../../playwright.config.js)に対応する。

## 1. 検証コマンド

```text
npm run check
npm run test:unit
npm run test:e2e
```

`npm run test:all`は上記を順に実行する。

編集scopeとSelectionの境界は`editing-workspace.test.js`、`selection.test.js`で検証する。DocumentとBlockの同一IDの独立性、scope復元、Canvasとツリーの選択同一性、寸法・Arc端点・拘束の優先順位、対象の種類別上限を確認する。これらも`test:unit`に含む。UIでのBlock確定・取消・保存往復は`free-instance.spec.js`、選択と操作は既存の関連E2Eで確認する。

`edit-history.test.js`は履歴instanceの独立性、記録上限、同じsignatureでのRedo保持、一時操作の履歴破棄、復元callbackが返す失敗・例外とstack移動の順序を検証する。DocumentとBlockのsnapshot形式、作図取消、実際のUndo／Redoは関連E2Eで確認する。

アプリケーション設定のstorage不使用時の保持、非永続化、翻訳と更新順序、eventの登録・解除は`application-settings.test.js`で確認する。実DOMの翻訳、テーマ、dialog、HelpのGit情報、`file:`起動は`unified-ui.spec.js`と`choice-dialog.spec.js`で確認する。

拘束参照の境界は`constraint-references.test.js`で確認する。端点順序とObject同一性、Arc／Splineの構成点、Offset chain両側の列挙、Block・派生Instance固有参照の展開、別scopeの参照解決を対象とする。UIでの削除・投影・Block編集・保存往復・dragは対応する既存E2Eで確認する。

`sketch-context.test.js`は、同一Sketch IDを使うscopeの切替、Geometryの明示所属と構成点からの補完、active・祖先参照元・子孫・無関係Sketchの区別、拘束の所属と操作対象の違いを検証する。

`module-loading.test.js`は`index.html`に記載した順序で全production moduleを初期化し、依存先の未読込と重複登録を検出する。独立したunit testの手動読込順だけで成功しても、実際の起動順が正しい保証にはしない。DOMを使うapp bootstrapと実行Git情報はbrowser E2Eで確認する。

`parameter-namespace.test.js`は寸法のtargetと幾何測定の違い、保存した角度領域、Document／Block間の採番分離、参照値と式の評価、度とradianの変換、評価失敗時の部分更新、version別の読込検証、入力式・名前置換・言語切替を検証する。操作全体のrollbackと保存往復は既存のParameter・Block E2Eで確認する。

Parameter名前空間の単体検証では保存・UI moduleを読み込まない。寸法の型判定・測定と式評価の依存だけで初期化・実行できることを確認する。

`instance-projection.test.js`は派生Geometryの参照同一性と元Geometryへの追従、順・逆変換、入力順の保持、scope間の同一ID分離、循環参照、所属条件、Mirror・Pattern、反転Arcと旧出力IDをDOMなしで検証する。Canvas・Block・拘束・保存と性能は既存E2Eで確認する。

`block-projection.test.js`はregistry差替え、入れ子の有効Sketch判定、cache再利用と部分・全無効化、投影点の追従と所有者、読込専用resolver、Block内の派生Instance、循環参照、Annotationの参照・外観・変換を検証する。Hatch投影と実際のBlock編集・保存・dragは既存E2Eで確認する。

`geometry-read-model.test.js`は同期読出し内の配列・Object・外観の共有、入れ子callback、例外時の解放、同一IDを持つscope間のcache破棄、HatchのないDocumentでの展開省略、一覧順序と参照解決、cache missの計測を検証する。SolverやDOMを読み込まず、読出しportを通じて検証できる構成を保つ。

外観・描画順・保存sessionの境界は`node --test tests/unit/appearance.test.js tests/unit/drawing-order.test.js tests/unit/document-files.test.js`でDOMなしに検証する。旧外観のmm変換とlayer優先順位、描画順の補完・移動とscopeの分離、保存中の追加編集・排他・書込み失敗を対象とする。これらは`test:unit`にも含む。実際のUI・保存往復・script読込は既存E2Eで確認する。

Documentの境界は`constraint-persistence.test.js`、`geometry-persistence.test.js`、`sketch-hierarchy.test.js`、`document-elements.test.js`、`document-snapshot.test.js`で検証する。いずれも`tests/unit/`にあり`test:unit`に含む。scopeごとの参照分離、旧形式の受理・拒否、親子走査、要素の同一性、保存fieldと採番値をDOMなしで確認する。`unified-ui.spec.js`のfile起動テストは責務別folderの全script読込・公開APIと起動ごとのcache回避queryを検証する。

ファイル操作の安全性は`npx playwright test tests/e2e/file-safety.spec.js`で検証する。未保存表示とUndo／Redo、保存して開く・キャンセル・破棄、遅い保存中の追加編集と重複防止、write／close失敗、API非対応時のダウンロード・読込、壊れたJSON、ブラウザ離脱確認を対象とする。書込み失敗はmockで再現し、ダウンロードは生成されたJSONを実際に読み戻す。

履歴・計測moduleだけを検証する場合は`node --test tests/unit/edit-history.test.js tests/unit/interaction-profiler.test.js`を実行する。DOMなしの環境でmoduleを読み、計測にはテスト用clockを渡す。実際の画面復元とscript読込はE2Eの検証範囲とする。

E2Eは性能閾値の測定が他workerのCPU飽和に左右されないよう1 workerで直列実行する。

拘束・ドラッグの実データ回帰は`npx playwright test tests/e2e/constraint-drag-regressions.spec.js`で実行する。`tests/fixtures/`に保持する6図面について、複数のつかむ位置、8方向、低速・高速の3往復、細かな連続入力を検証する。各previewで元の拘束残差、自由度、Geometryごとの拘束状態を確認し、ドラッグ終了時の残差と追従量も確認する。参照画像はこの計算用fixtureから除いているため、画像の描画負荷はこのsuiteの測定範囲に含まれない。

## 2. 実行環境と対象の選択

全E2Eには、`tests/fixtures/`の管理対象データに加えて、Git管理外の`test-data/テスト図形.json`と`test-data/意地悪ドラッグ完全拘束.json`が必要になる。前者は既存図面の互換性・ドラッグ検証用データを配置する。後者は`node tools/generate-adversarial-drag-fixture.js`でも生成できる。比較実行では同一内容を使用し、データ未配置によるテスト収集エラーを実装の失敗と混同しない。

Node.js・npmとプロジェクトの依存パッケージ、Playwrightが使用するbrowserを用意する。Playwright設定のwebServerが全suite共通のHTTP serverを自動起動するため、事前の`npm run serve`は不要。既定のbaseURLは`http://127.0.0.1:8765`で、環境変数`JOT2D_E2E_PORT`で全suiteのportをまとめて変更できる。suite別のport加算は行わない。

同じbaseURLで起動済みの本リポジトリのserverがあれば再利用し、テスト終了時に停止しない。Playwright自身が起動したserverは終了時に停止する。別アプリのportは指定しない。通常起動の共通helperはtest modeのページを開いてhook準備を待つだけで、図面読込・履歴初期化・viewport設定は各ケースが明示する。`file:` URL専用ケースは引き続き直接fileを開く。

Windowsの制限された実行環境でプロセスツリーの停止が許可されていない場合は、テスト成功後にserver終了待ちになることがある。serverを起動・停止できる実行環境を使うか、同じbaseURLで事前起動したserverを再利用する。

```text
npm run test:e2e -- tests/e2e/blocks.spec.js
npm run test:e2e -- --list
```

PowerShellで別portの自動起動を確認する例：

```powershell
$env:JOT2D_E2E_PORT = '18765'
try { npm run test:e2e -- tests/e2e/drawing-order.spec.js }
finally { Remove-Item Env:JOT2D_E2E_PORT }
```

結果の報告では通常の成功、失敗を期待するテスト（expected failure）、skip、予期しない失敗を区別する。実行コマンドの終了コードが0でも、既知不具合を示すexpected failureが残ることがある。

`--list`はテストの列挙のみで、成功を検証したことにはならない。`npm run check`はJavaScript構文検査であり、型検査・lint・buildではない。これらの専用scriptは現在定義されていない。

文書のみの移動ではリンク・見出し・台帳と本文の保持を確認する。挙動・計算・UIを変更した場合は、対応する既存テストと必要な追加検証を実施し、実行対象・結果・未確認範囲を記録する。

## 3. Visual baseline

`phase0-characterization.spec.js`は現在の単一Canvas layoutで、Geometry／Constraint、入れ子Block、Sketch所属Annotation、Reference Image commandを含むToolbar、Block EditorのCanvas baselineを保持する。UI構造変更時は意図を確認してbaselineを更新する。

## 4. 変更時の確認

仕様変更では実装、関連spec、unit／E2E、visual baselineを同一変更で更新する。旧モードやSheetを前提とするUI selectorおよび保存fieldを現行テストへ持ち込まない。ただし旧JSON破棄を確認するfixtureに限り旧fieldを入力データとして保持できる。

## 5. ドラッグの処理別測定

```text
npx playwright test tests/e2e/adversarial-authoring-performance.spec.js --grep "coalesce to one" --repeat-each=3 --reporter=line
```

既存のGeometry・寸法・Panの高密度pointer入力テストは、入力集約の回数とpreview／commitの処理別時間をJSONで出力する。高密度はpointer入力密度を指し、このケース自体はsampleModelを使う。大規模fixtureの性能保証は同suiteの他ケースとdrag専用suiteで扱う。

test modeのstartInteractionProfileForTestで開始し、stopInteractionProfileForTestで結果を取得して無効化する。開始前に残ったpointer入力はflushして計測対象から除く。通常実行では無効。phaseごとにsamples、totalMs、maxMs、otherMs、およびwork内のcalls・selfMsを記録する。selfMsは計測された子処理を除いた時間で、全区分のselfMsとotherMsの和がtotalMsになる。関数と区分は[実装対応表](../../docs/refactoring/implementation-map.md#7-ドラッグの計測と更新境界)で確認する。

計測は同期JavaScriptの経過時間であり、event待ち・rAF待ち・GPU描画・画面合成を含まない。関数内で起きた同期layoutはその関数の時間に含む。clock取得・集計負荷も含む診断値なので、既存の性能閾値とは別に扱う。無効時はclock取得・集計を行わないが、入口の分岐と関数呼出しは残る。比較では同じfixture・環境・入力・計測点を用い、短時間の単発差を高速化と断定しない。

報告図面の代表対象は、通常のファイル取込と実際のPointerイベントでも選択対象のID、往復中の拘束状態、Undo／Redo、保存データの再読込を検証する。短い円弧では、固定・オフセット拘束が所有する端点を読込時の表示補正で変更しないことを確認する。
