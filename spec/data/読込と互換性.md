# 読込と互換性

現行の保存構造は[保存形式](./保存形式.md)、pickerと保存先の扱いは[ファイル操作](../operations/ファイル操作.md)に従う。

## 1. 読込と互換性

### 読込結果の分類

読込は、保存versionに応じた移行と各データの検証を行う。構造として不正なデータと、読み込んで保持できる無効状態を区別する。

| ID | 条件 | 結果 |
| --- | --- | --- |
| LOAD-01 | 必須構造、Geometry参照、式などが下記の検証条件を満たさない | 問題のsymbolまたはObjectと理由を通知し、読込全体を拒否する。現在のDocumentを維持する |
| LOAD-02 | 復元できる参照拘束がSketchの参照範囲外、または循環参照になる | 該当拘束を無効扱いとして保持し、エラー表示する。solve対象から除外する |
| LOAD-03 | Block内部拘束の参照先が失われており復元できない | 該当拘束を解除し、解除件数を通知して読込を継続する。ただし下記の明示的な拒否条件を優先する |
| LOAD-04 | 構造が正しいHatchで、境界Geometryが欠落している、または境界の位相を復元できない | Hatchを無効状態で保持する。境界の問題だけでは読込全体を拒否しない |
| LOAD-05 | 対応する旧versionのデータ | 下記の移行を適用し、現行モデルへ正規化する |

LOAD-02は、参照拘束そのものと参照するGeometryを復元できることが前提である。Geometryが存在せずDocument直下の拘束を復元できない場合や、Block Definitionの循環、派生Instanceの不正を受理する規則ではない。

### 検証条件

以下の不正はLOAD-01として扱う。DocumentとBlock Definitionの両方にあるデータは、それぞれのscopeで検証する。

| 対象 | 適用するversion | 検証する条件 |
| --- | --- | --- |
| Documentの長さ単位 | 20以降 | `units`が存在し、`length`が`"mm"`である |
| 派生Instance | 21以降は配列必須 | `geometryInstances[]`の種類、所属Sketch、GeometryRef、ミラー軸、パターン方向・間隔・コピー数、および解決可能な依存関係 |
| Reference Image | 18以降 | 配列、画像データ、変換・表示設定、および作図可能Sketchへの所属。詳細は[Reference Image](#reference-image) |
| Parameter・寸法symbol | 17以降は引用形式。旧版は移行後に検証 | 識別子、重複、予約名、式の構文、引用された参照識別子、未定義参照、循環参照、ゼロ除算、非有限値 |
| Spline | 15以降 | `splines[]`、ID、定義方式・次数・端条件、所属Sketch、fit point参照、開閉、construction、Appearance。詳細は[Spline](#spline) |
| Annotation・Leader | 11以降は所属を検証。旧版は移行 | Annotationが同じscopeのRoot以外のSketchに所属し、Leaderが同じ所属SketchのGeometryを参照する |
| Hatch | 13以降 | 配列、採番値、所属、seed、境界記述、Appearance構造。`patternType`は`parallel`、`cross`、`solid`だけを受理する。境界欠落・位相不成立はLOAD-04として区別する |
| チェーンオフセット拘束 | 14以降 | `offsetChainDimension`の順序付き参照構造。Block内部でも不正なら拒否し、LOAD-03による解除へ置き換えない |
| 中心線拘束 | 現行 | `parallelLinesCenterline`と`pointPairCenterline`を受理する。16以降の旧`pointOnLineMidpoint`は拒否する |
| Block Definitionの所有・依存関係 | 読込時 | 親の存在、複数親・自己参照・循環の禁止、および親以外からの不正な子Definition参照。詳細は[ブロック](../operations/Block.md) |

### 旧versionからの移行

各行は入力versionの条件に従って適用する。該当する複数の移行を組み合わせ、保存済みの参照関係と意味を維持する。

| 入力 | 対象 | 移行後 |
| --- | --- | --- |
| 21以前、または描画順の不足 | 共通描画Object | 下記の「描画順の正規化」に従って`drawingOrder`を補完する |
| 19／20 | 通常Geometryと`sketchProjection`拘束 | 1拘束につき1個の派生Instanceへ移行し、旧投影先Geometryを通常配列から除く。旧IDを`legacyOutput`で維持し、Constraint・Leader・Hatch参照を保つ |
| 18以前 | スケッチ投影 | `sketchProjection`拘束なしとして扱う |
| 19以前 | Document単位 | `units: { length: "mm" }`を補完し、モデル数値を変換せずmmとして扱う |
| 17以前 | Reference Image | Documentと各Block Definitionに空の`referenceImages[]`を補完する |
| 16以前 | Parameter・寸法の式 | 引用されていない識別子をダブルクオーテーションで括る。既に引用されている参照、数値、科学表記、演算子、括弧は維持する |
| 15以前 | 旧`pointOnLineMidpoint`拘束 | 旧拘束を破棄し、保存Point座標を維持する |
| 14以前 | Spline | Documentと各Block Definitionに空の`splines[]`を補完する |
| 12以前 | Hatch | `hatches: []`と`nextHatchIndex: 1`を補完する |
| 11以前 | Dimension Appearance | 長さ値を`mm = px × 25.4 / 96`で変換し、`arrowheadLength`を`terminatorSize`へ移す。旧`arrows`と`extensionLines`は破棄する |
| 10以前 | Annotation所属 | 下記の「Annotation所属の補完」に従う |
| 9以前 | 寸法symbol | 名前空間ごとの寸法配列順に`d1`以降を付ける。拘束寸法の既存`target`をmmの数値式へ変換し、参照寸法には名前だけを付ける |
| 旧表示専用データを含むJSON | モード、Sheet、Sheet style、Sheet annotation | 現行モデルへ移行せず破棄する |

旧Geometry、Constraint、Sketch、Blockの不足fieldは、対応する現行構造へ補完・正規化する。Block内部Sketchの旧データ移行とProjection ID維持は「field欠落と旧外観の補完」に従う。

### 描画順の正規化

version 22では、Document直下と各Block DefinitionのLine、Circle、Arc、Spline、Hatch、Block Instance、派生Geometry Instanceに`drawingOrder`を保存する。

- 順序は同じSketch内だけで比較し、0から始まる連続した非負整数へ正規化する。
- 旧データで順序がない場合は、Hatchを背面に置く。その上へLine、Circle、Arc、Spline、Block Instance、派生Geometry Instanceを配列順で並べ、従来表示を維持する。
- 一部だけに有効な順序がある場合は相対順を保ち、不足するHatchを背面、その他のObjectを前面へ補う。

### Annotation所属の補完

version 10以前では、次の規則で所属Sketchを補完する。

| 対象 | 所属の決定 |
| --- | --- |
| DocumentのLeader | 解決できる参照GeometryのSketch |
| DocumentのFree Text | 保存時のactive Sketch |
| 上記がRootまたは参照不能 | 最初の作図可能Sketch |
| Block DefinitionのLeader | Definition内の参照先Sketch |
| Block DefinitionのFree Text | Definitionのactive Sketch |

### 保存往復の保証

保存→読込→保存で、現行fieldの意味とIDを維持する。`savedAt`以外の現行データは反復round-tripで安定する。

## 2. field欠落と旧外観の補完

- 旧JSONなどで`defaultConstructionAppearance`がない場合は、表示あり、`#64748b`、一点鎖線、1px、端部のはみ出しあり、端部の点ありとして補完する。
- 旧データのDocument Rootに保存された外観は読込時にDocument既定へ移し、Block DefinitionのRootに保存された外観は内部の各子Sketchへ移して表示を維持する。
- 旧JSONにSketchの`constructionAppearance`／`dimensionAppearance`がない場合は空の部分上書きとして読み込み、Document既定表示を維持する。
- 旧`style.fontSize`は読込時に`fontSize / (96 / 25.4)`で`textHeight`へ変換し、保存時は`fontSize`を出力しない。

旧Definitionに内部Sketchがなければ `Root Sketch -> Sketch-1` へ移行する。旧Projection IDは `instanceId@elementId` として維持する。

## 3. 機能別の検証詳細

### Reference Image

version 18以降で配列、MIME、Data URL、pixel寸法、有限な配置値、正のscale、不透明度、boolean field、所属Sketchが不正な場合はDocument全体の読込を拒否して読込前状態を維持する。

### Spline

version 15以降で配列欠落、不明な定義方式・次数・端条件、不正なfit point参照、3点未満、隣接重複、異なるSketch参照がある場合はLOAD-01として読込全体を拒否し、現在のDocumentを維持する。

### Hatch

Documentと各Block Definitionの配列、採番値、ID、所属Sketch、seed、境界記述、完全Appearanceの構造を検証する。opacityは0～1だけを受理し、fieldが省略されている場合は後方互換のため1へ補完する。不正ならLOAD-01に従う。patternTypeの許可値と境界欠落の扱いは上表のHatch検証条件とLOAD-04に従う。
