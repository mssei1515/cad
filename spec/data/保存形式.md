# 保存形式

現行Document JSONの構造とfieldを定義する。入力の検証・旧版移行は[読込と互換性](./読込と互換性.md)、操作は[ファイル操作](../operations/ファイル操作.md)に従う。

## 1. Document JSON

保存ファイルの正式な拡張子は`.jot2d`とし、内容はversion 22のDocument JSONとする。拡張子の変更によってJSONのfieldや構造は変更しない。

```text
document
  version: 22
  documentName
  units
    length: "mm"
  parameters[]
  nextDimensionParameterIndex
  defaultAppearance
  defaultConstructionAppearance
  defaultDimensionAppearance
  sketches[]
  activeSketchId
  points[] / lines[] / circles[] / arcs[] / splines[]
  constraints[]
  blockDefinitions[]
  blockInstances[]
  geometryInstances[]
  annotations[]
  hatches[]
  referenceImages[]
  nextHatchIndex
  savedAt
```

表示モード、Sheet、active Sheetは保存しない。

Documentのモデル長さはmmへ固定する。Point座標、Circle／Arc半径、拘束寸法、Block Instanceの配置、Annotation位置、Hatch seed、Reference Imageのworld寸法など、モデル空間に属する長さはすべてmmとして保存・計算する。`units.length`は常に`"mm"`であり、単位変更によるGeometryの再解釈や拡大縮小は行わない。Dimension Appearance、AnnotationおよびHatchで画面上の大きさを指定する概算mmはモデル長さとは別の表示属性である。

ファイルハンドルはDocument JSONへ保存しない。保持範囲は[ファイル操作](../operations/ファイル操作.md#2-保存先ハンドルの保持範囲)に従う。

## 2. Appearance

Appearanceは次の部分オブジェクトである。

| field | 型 | 意味 |
| --- | --- | --- |
| `visible` | boolean | 通常表示で描画・hit対象にするか |
| `color` | CSS color string | 線・点の通常色 |
| `lineType` | `solid` / `dashed` / `dashdot` / `dashdotdot` / `dotted` | 実線／破線／一点鎖線／二点鎖線／点線 |
| `lineWidth` | number | 画面上の線幅 |
| `endpointOverhang` | boolean | 補助Lineを両端から延長して描画するか |
| `endpointMarkers` | boolean | 補助Lineの元の両端に点を描画するか |

`defaultAppearance`はvisible、color、lineType、lineWidthをすべて持つ。`defaultConstructionAppearance`は補助Geometryへ適用するDocument既定であり、visible、color、lineType、lineWidth、endpointOverhang、endpointMarkersをすべて持つ。これらと`defaultDimensionAppearance`はDocument設定UIから編集する。継承経路は[表示と注記](../ui/表示とビュー操作.md)の「Appearanceの継承」に従う。endpointOverhangとendpointMarkersは補助Lineの描画だけに使用する。

Root以外の各Sketchは通常Geometry用の`appearance`、補助Geometry専用の部分上書き`constructionAppearance`、寸法専用の部分上書き`dimensionAppearance`を持つ。Root Sketchの3つのfieldは空Objectとして保存し、表示解決や編集には使用しない。各Geometryは`appearance`、Block Instanceは`appearanceOverride`を持つ。Block Editor内の外観と配置先のProjection外観は[表示と注記](../ui/表示とビュー操作.md)で区別する。

## 3. Geometry

Point、Line、Circle、Arcは従来の幾何情報に加えて`sketchId`と`appearance`を持つ。Line、Circle、Arcは`construction`を持つ。Line、Circle、ArcおよびSplineは、同じSketch内の共通重なり順を表す非負整数`drawingOrder`を持つ。

Document直下と各Block Definitionに`splines[]`を必須配列として保存する。Splineは次を保持する。

```text
splines[]
  id
  definitionMode: "fit"
  degree: 3
  fitPoints[]       // 3個以上のPoint ID
  closed
  endCondition: "natural"
  construction
  sketchId
  drawingOrder
  appearance
```

Splineの方式と開閉の補間は[幾何計算](../calculation/幾何計算.md#3-splineの補間)に従う。fit pointは同じscope・同じSketchの通常Pointを参照し、隣接する同一点参照、3点未満、存在しないPointを含む現行JSONは不正とする。詳細は[スプライン](../operations/Spline.md)を参照する。

Block Projectionは保存せず、DefinitionとInstanceから生成する。ProjectionのGeometryRefは`{ kind, path[] }`を正規形とし、保存文字列では`BI1@B2I1@L1`のようにpathを`@`で結合する。

スケッチ投影、ミラー、直線パターンは`geometryInstances[]`へ保存し、表示Geometryを参照元から動的に生成する。生成Geometry自体は通常Geometry配列へ保存しない。GeometryRefは通常Geometry、Block Projection、派生Geometryを同じ`{ kind, path[] }`形式で参照する。詳細は[派生Geometryインスタンス](../operations/派生Instance.md)を参照する。

## 4. Sketch

Sketchは`id`、`name`、`parentSketchId`、`kind`、`appearance`、`constructionAppearance`、`dimensionAppearance`を持つ。ROOTは階層ルートであり、通常Geometryの作成先にはしない。

## 5. Block

Block Definitionはローカル座標のSketch、Splineを含むGeometry、Constraint、Annotation、Hatch、編集用Reference Image、子Block Instance、派生Geometry Instanceに加え、Definition固有の`parameters[]`、`nextDimensionParameterIndex`、`nextHatchIndex`を保持する。Document直下と各Block Definitionはそれぞれ独立した`annotations[]`、`hatches[]`、`referenceImages[]`、`geometryInstances[]`を持つ。Definition内部のReference ImageはBlock Editorでだけ使用し、Block Instanceへ投影しない。Block Instanceは配置`x`、`y`、`rotation`、固定状態、有効内部Sketch、`appearanceOverride`、`drawingOrder`を保持する。派生Geometry Instanceも同じSketch内の共通重なり順を表す`drawingOrder`を持つ。Block Instanceと派生Geometry Instanceは、生成物ごとではなくInstance全体を1つの描画Objectとして扱う。

Appearance OverrideはInstance全体への一括Overrideであり、そのInstanceから展開されるすべてのProjection GeometryおよびProjection Annotationへ適用する。

## 6. Constraint Dimension Appearance

Documentは拘束寸法・参照寸法の既定値である`defaultDimensionAppearance`を持つ。所属Sketch自身の`dimensionAppearance`だけを適用し、その後に寸法ごとの部分上書きである`dimension.display`を適用する。既存JSONとの互換性のためfield名は`display`を維持するが、UIおよび仕様上はDimension Appearanceとして扱う。

```text
defaultDimensionAppearance / sketch.dimensionAppearance / dimension.display
  visible
  color           // #rrggbb
  lineWidth       // 画面上の線幅（px）
  precision       // nullは自動
  prefix
  suffix
  toleranceUpper  // nullはなし
  toleranceLower  // nullはなし
  terminatorType          // arrow / filledArrow / dot
  terminatorSize          // 矢印の長さまたは点の直径（mm）
  extensionLineOvershoot  // 寸法補助線の突出量（mm）
  extensionLineOriginGap  // 寸法補助線の起点すき間（mm）
  arrowheadAngle          // 矢印を構成する2辺の開き角（度）
  dimensionTextHeight     // 寸法文字の高さ（mm）
  dimensionTextGap        // 寸法文字領域と寸法線との間隔（mm）
```

`defaultDimensionAppearance`は全fieldを持つ。Sketchの`dimensionAppearance`と`dimension.display`は明示変更したfieldだけを持ち、省略fieldはそれぞれDocument既定または所属Sketchの実効値を継承する。寸法の個別Colorまたは線幅を空にすると上書きを削除し、所属Sketchで解決した値へ戻る。端末記号は左右共通で、標準矢印、塗りつぶし矢印、点から選択する。寸法補助線と端末記号は常時表示し、表示切替fieldは持たない。初期値は表示あり、`#64748b`、線幅1.2px、精度自動、空のPrefix／Suffix、標準矢印、突出量1.5mm、起点すき間1.5mm、端末サイズ4mm、開き角30°、文字高さ5mm、文字間隔0mmとする。

`toleranceUpper`と`toleranceLower`は既存JSONとの互換性のためデータモデルに保持するが、現在のProperties UIでは編集項目を表示しない。

すべての拘束寸法と参照寸法は`parameterName`を持つ。拘束寸法は正式な入力値として`expression`を保存し、その評価結果を既存の`target`へsolver用cacheとして反映する。version 17の`expression`でParameterまたは寸法symbolを参照する場合は`"width"`や`"d1"`のように識別子をダブルクオーテーションで括る。参照寸法はGeometryから測定するため式を持たず、`target`を入力値として扱わない。別の注記寸法データは持たない。

version 14の複数GeometryオフセットはConstraint型`offsetChainDimension`として保存する。`sources[]`は基準Line／ArcのGeometry IDと`reversed`を順序付きで持ち、`offsets[]`は対応する結果Geometry IDを同じ順序で持つ。さらに共通距離`target`、左右を示す`side`、`closed`、固定値`joinType: "miter"`、寸法表示対象の`dimensionSegmentIndex`、通常の寸法fieldを保持する。基準と結果は2要素以上かつ同数・同種でなければならず、不正な現行データは読込を拒否する。version 13以前にはこの型が存在しないため追加の移行は行わない。

Documentおよび各Block Definitionは次を持つ。

```text
parameters[]
  name
  expression
nextDimensionParameterIndex
```

`nextDimensionParameterIndex`は新規寸法名`d1`、`d2`、…の単調増加counterであり、削除済み番号を再利用しない。

## 7. Annotation

`annotations[]`に次を保存する。

- Leader: `id`、`sketchId`、`visible`、`geometryRef`、`start`、`elbow`、`end`、`x`、`y`、`rotation`、`text`、`style`
- Free Text: `id`、`sketchId`、`visible`、`x`、`y`、`rotation`、`text`、`style`

すべてのAnnotationはRoot以外の作図可能Sketchに所属する。Leaderの`geometryRef`は同じ所属Sketch内のGeometryまたは、そのSketchに配置されたBlock Projectionを参照し、Geometryの移動に追従するアンカーを解決する。参照Geometryを削除した場合は該当Leaderも削除する。Annotationの`style`はcolor、概算mmの`textHeight`、fontFamily、bold、italic、textAlignを完全値で保持し、Leaderではさらに画面pxのlineWidth、`solid`／`dashed`／`dashdot`／`dashdotdot`／`dotted`のlineType、terminatorType、概算mmのterminatorSizeを保持する。Sketch一般Appearanceは継承せず、Sketchから受けるのは表示状態だけである。

Block Projection Annotationは保存せずDefinitionとInstanceから導出する。IDは`BI1/AN1`、入れ子では`BI1/BI2/AN1`のように最上位Instanceからのpathを`/`で連結する。座標、Leader折線、文字位置、回転、GeometryRefはInstance変換を合成し、投影先Sketchは最上位Instanceの配置Sketchとする。

## 8. Hatch

`hatches[]`は`id`、`sketchId`、同じSketch内の共通重なり順`drawingOrder`、作成位置`seed`、外周と穴の`boundaryLoops`、完全値の`appearance`を持つ。境界spanは座標copyではなく、Line／Circle／Arc／SplineのGeometryRef、端点または交差相手と交点順、進行方向、完全Circle／閉Spline区分を保存する。Appearanceはvisible、`parallel`／`cross`／`solid`のpatternType、angle、画面mm表記のspacing、color、画面pxのlineWidth、0～1のopacityから成り、Document／Sketch Appearanceを継承しない。`solid`ではcolorとopacityを面の塗りへ使用し、angle、spacing、lineWidthは保存するが描画には使用しない。詳細は[ハッチング](../operations/Hatch.md)を参照する。

```text
hatch
  id                    // H1, H2, ...
  sketchId
  drawingOrder          // 同じSketch内の共通重なり順
  seed { x, y }         // 作成または境界再指定時のclick位置
  boundaryLoops[]
    role                // outer / hole
    spans[]
      source            // 既存Line／Circle／Arc／SplineのGeometryRef
      start / end       // endpointまたは交差相手と交点順
      reversed          // 曲線の進行方向
      fullCircle        // 交点のない完全Circle
      fullLoop          // 交点のない閉Spline
  appearance
    visible
    patternType         // parallel / cross / solid
    angle               // degree
    spacing             // 画面上の概算mm
    color
    lineWidth           // 画面px
    opacity             // 0.0～1.0。solidの塗りに使用
```

## 9. Reference Image

`referenceImages[]`は`id`、`name`、`sketchId`、MIME、Base64 Data URL、pixel幅・高さ、mm座標上の中心`x`／`y`、pixel当たりの正のmm長さ`scale`、radianの`rotation`、0～1の`opacity`、`visible`、`locked`を持つ。MIMEはPNG、JPEG、WebPだけとし、長辺は3000px以下、scaleは縦横共通とする。画像はConstraint、solver、snap、Hatch境界、Block Projectionへ参加しない。詳細は[参照画像](../operations/参照画像.md)を参照する。

```text
referenceImages[]
  id                // IMGn
  name
  sketchId
  mimeType          // image/png | image/jpeg | image/webp
  dataUrl           // data:<mimeType>;base64,...
  pixelWidth        // 1..3000
  pixelHeight       // 1..3000
  x / y             // 画像中心のmm座標
  scale             // 正のmm/pixel
  rotation          // radian
  opacity           // 0..1
  visible
  locked
```

画像binaryはBase64 Data URLとして`.jot2d`内へ埋め込み、再読込時に復元する。Document直下と各Block Definitionで配列を必須とする。

## 10. ID

通常Geometryは既存の`P`、`L`、`C`、`A`に加えてSplineの`SP`、Sketchは`S`、Block Definitionは`B`、Block Instanceは`BI`、スケッチ投影Instanceは`SPI`、ミラーInstanceは`MI`、パターンInstanceは`PI`、Annotationは`AN`、Hatchは`H`、Reference Imageは`IMG`を接頭辞とする。`nextHatchIndex`は削除済みHatch番号を再利用しないための単調増加counterである。読込時は既存IDと保存済みcounterから次の採番値を予約する。

## 11. 派生Geometry Instance

JSON version 21以降の派生Instanceは次の形式を使い、現行versionでは各Instanceへ同じSketch内の共通重なり順`drawingOrder`も保存する。

```js
{
  id: "SPI1" | "MI1" | "PI1",
  type: "sketchProjection" | "mirror" | "pattern",
  sketchId: "S1",
  sources: [{ kind: "line", path: ["L1"] }],
  axis: { kind: "line", path: ["L2"] },       // mirrorのみ
  direction: { kind: "line", path: ["L3"] },  // patternのみ
  spacing: 10,                                    // patternのみ、mm
  copies: 2,                                      // patternのみ、元を除く
  reversed: false,                                // patternのみ
  appearanceOverride: {}
}
```

生成IDはインスタンスID、パターンの出現番号、参照元GeometryRef pathを`@`で連結する。各出現内のPointも同じ原則で安定したIDを持つ。

## 12. 編集中データとClipboard

Parameter、寸法名、式、採番counterはDocument、Block Definition、History、Block Editor draft、clipboardへ保存する。チェーンオフセット寸法はチェーン全体で1つの寸法symbolと式を持つ。

History、Block Editor draft、ClipboardにもSplineとfit point、拘束、参照を含める。履歴全体の保持範囲は[編集と履歴](../contracts/編集と履歴.md)に従う。

## 13. GeometryRefとConstraint参照

GeometryとBlock Projectionの参照は`GeometryRef { kind, path[] }`として扱う。kindは`point`、`line`、`circle`、`arc`、`spline`のいずれかで、pathは1要素以上の文字列配列である。通常Geometryのpathは`["L1"]`、入れ子Projectionは`["BI1", "BI2", "L1"]`のように表す。保存するIDはpathを`@`で連結する。

Constraintの各Geometry参照fieldは保存形式上は従来どおりbare IDを使う。例えば入れ子Projectionを参照するLine拘束は`"line": "BI1@BI2@L1"`となり、kindを保存文字列へ追加しない。保存時はGeometryの型とIDから共通codecでcanonical IDを生成し、読込時はConstraint fieldが要求するkindとbare IDから共通resolverで実体を引く。

複数kindを許すfieldの解決順は次のとおりである。

- Offsetのsource／offsetはLine、Circle、Arcの順に解決する。
- Concentricのa／bはPoint、Circle、Arcの順に解決する。
- CircleまたはArcを許すprimitive fieldはCircle、Arcの順に解決する。

参照を解決できない場合のConstraint読込エラーと、Constraint型ごとの保存・復元規則は従来どおりである。

値とpathは不変であり、空path、不明kind、空のpath要素は有効な参照ではない。ancestor Instanceは末尾のGeometry IDを除くpath、owner InstanceはProjection pathの先頭、local elementは末尾として取得する。

Leaderはkind付きGeometryRefを使い、同じresolver契約でProjectionを解決する。
