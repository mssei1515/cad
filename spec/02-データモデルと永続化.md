# データモデルと永続化

## 1. Document ルート

現在の保存形式は JSON `version: 8` である。

```text
Document
  version: 8
  savedAt
  documentName
  appMode
  sketches[]
  activeSketchId
  presentationSheets[]
  activePresentationSheetId
  blockDefinitions[]
  blockInstances[]
  points[]
  lines[]
  circles[]
  arcs[]
  constraints[]
```

`savedAt` は保存データ生成時刻であり、Document の意味的状態には含めない。画面のパン・ズーム位置、サイドバーの開閉、現在の選択、実行中コマンド、クリップボードは保存しない。

## 2. ID

通常生成される ID は次の接頭辞を使う。

| 対象 | 形式 | 例 |
| --- | --- | --- |
| Point | `P<n>` | `P12` |
| Line | `L<n>` | `L4` |
| Circle | `C<n>` | `C2` |
| Arc | `A<n>` | `A7` |
| Sketch | `S<n>` | `S3` |
| Presentation Sheet | `PS<n>` | `PS2` |
| Presentation Element | `PE<n>` | `PE8` |
| Block Definition | `B<n>` | `B3` |
| Block Instance | `BI<n>` | `BI5` |

Root Sketch は固定 ID `ROOT` である。

読込時は既存 ID から次の採番値を予約する。Presentation Sheet と Definition の重複 ID は補正するが、通常 Geometry の全 ID を包括的に重複検証する処理はない。Block Definition 内では Point、Line、Circle、Arc、子 Block Instance をまたぐ重複 ID を編集完了時に拒否する。

## 3. Sketch と Geometry

```text
sketch
  id
  name
  parentSketchId
  kind: "root" | "sketch"
  visible

point
  id
  x, y
  fixed
  kind: "explicit" | "endpoint"
  sketchId

line
  id
  p1, p2                  # Point ID
  construction
  sketchId

circle
  id
  center                  # Point ID
  radius
  construction
  sketchId

arc
  id
  center                  # Point ID
  radius
  startAngle, endAngle    # radian
  construction
  sketchId
```

`endpoint` Point は Line の端点と Circle/Arc の中心に使う。孤立し、拘束からも参照されない endpoint Point は読込時に除去する。

## 4. Constraint

Constraint は型ごとに対象 ID と固有パラメータを保存し、共通して次の項目を持ち得る。

```text
constraint
  type
  enabled
  sketchId
  reference              # 別 Sketch 参照なら true
  referenceSketchId
  readOnlyDimension      # 重複寸法、または単一 Block 内実測寸法
  dimension              # 寸法表示がある場合
```

`readOnlyDimension` は読込時に `enabled = false` とし、solve 式に加えない。`dimension` は寸法線とラベルの配置、軸、角度寸法の反転・半径・ラベルオフセットを保持する。

Constraint の型一覧は [Geometry と拘束](./03-Geometryと拘束.md) を参照する。

## 5. Block

```text
blockDefinition
  id, name
  parentDefinitionId
  revision
  origin { x, y }
  sketches[]
  activeSketchId
  points[], lines[], circles[], arcs[]
  blockInstances[]
  constraints[]

blockInstance
  id
  definitionId
  sketchId
  x, y
  rotation
  fixed
  rotationLocked
  enabledSketchIds[]
```

Definition の内部 Geometry はローカル座標である。入れ子の子 Definition は `parentDefinitionId` により1つの親スコープへ所属し、その親 Definition 内の `blockInstances` から参照される。

Projection の安定 ID は、最上位 Instance からのパスを `@` で連結する。

```text
BI1@L3
BI1@BI7@C2
```

Projection 自体は JSON に保存しない。

## 6. Presentation

```text
presentationSheet
  id, name
  visibleGeometrySketchIds   # 保存されるが現在の描画では未使用
  elementStyles              # Geometry 要素キー -> style override
  elements[]                 # annotationDimension | leader
```

Geometry のスタイルキーは `<kind>:<elementId>` である。

```text
line:L1
circle:C2
line:BI1@L3
arc:BI1@BI7@A2
```

Presentation Element の詳細は [Presentation](./06-Presentation.md) を参照する。

## 7. 保存と読込

### 保存

1. 実行時オブジェクト参照を ID に変換する。
2. `version: 8` と `savedAt` を付ける。
3. 2スペースインデントの JSON を Blob としてダウンロードする。
4. ファイル名は Document 名を基にし、Windows で使用できない文字を `_` に置換する。

Block Editor を開いている間は保存できない。

### 読込

1. `points`、`lines`、`constraints` が配列であることを最低条件として検証する。
2. Sketch、Block、Presentation の不足項目を既定値で補う。
3. ID から Geometry オブジェクト参照を再構築する。
4. Block の親所有権と循環参照を検証する。
5. Projection を再構築して外部拘束を復元する。
6. 短すぎる Line を可能な範囲で最小長へ補正する。
7. 寸法表示の不足値を補い、採番値を予約する。
8. solve、全 Geometry へのフィット、履歴初期化を行う。

旧データに Sketch がなければ `Root Sketch -> Sketch-1` を作る。旧 Block Definition に内部 Sketch がなければ同様に内部 Sketch を作り、既存要素を `Sketch-1` へ所属させる。

保存形式の `version` に応じて段階的に migration を分岐する仕組みはなく、現行 loader が欠損フィールドを都度補正している。

## 8. 参照削除

Geometry、Sketch、Block Projection が削除されると、次を同時に整理する。

- 対象 Geometry を参照する Constraint
- Presentation Sheet の該当 `elementStyles`
- 対象を参照する注記寸法と引出線
- Sketch 削除時の `visibleGeometrySketchIds` 内 ID

現在は参照切れ状態を保存せず、Presentation Element は自動削除する。これが望ましい製品仕様かは [Presentation](./06-Presentation.md) の議論事項とする。

## 9. 履歴スナップショットとの違い

通常の Undo/Redo は保存 JSON とほぼ同じスナップショットを使うが、次を除外する。

- `savedAt`
- `documentName`

したがって Document 名変更は履歴対象外である。Construction 作図モードもスナップショット外だが、Undo/Redo 前の値を明示的に維持する。画面のパン・ズームも履歴対象外である。

通常履歴と Block Editor 内履歴は独立し、それぞれ最大80スナップショットを保持する。
