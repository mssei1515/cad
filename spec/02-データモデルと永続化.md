# データモデルと永続化

## 1. Document JSON

保存形式はversion 10とする。

```text
document
  version: 10
  documentName
  parameters[]
  nextDimensionParameterIndex
  defaultAppearance
  defaultConstructionAppearance
  sketches[]
  activeSketchId
  points[] / lines[] / circles[] / arcs[]
  constraints[]
  blockDefinitions[]
  blockInstances[]
  annotations[]
  savedAt
```

表示モード、Sheet、active Sheetは保存しない。

## 2. Appearance

Appearanceは次の部分オブジェクトである。

| field | 型 | 意味 |
| --- | --- | --- |
| `visible` | boolean | 通常表示で描画・hit対象にするか |
| `color` | CSS color string | 線・点の通常色 |
| `lineType` | `solid` / `dashed` / `dashdot` / `dotted` | 線種 |
| `lineWidth` | number | 画面上の線幅 |
| `endpointOverhang` | boolean | 補助Lineを両端から延長して描画するか |
| `endpointMarkers` | boolean | 補助Lineの元の両端に点を描画するか |

`defaultAppearance`はvisible、color、lineType、lineWidthをすべて持つ。`defaultConstructionAppearance`は補助Geometryへ適用するDocument既定であり、color、lineType、lineWidth、endpointOverhang、endpointMarkersを既定で持ち、必要に応じてvisibleも保持する。旧JSONなどで`defaultConstructionAppearance`がない場合は、従来表示と同じ灰色、一点鎖線、1.1px、端部のはみ出しあり、端部の点ありとして補完する。Sketch、Geometry、Block Instance Overrideでは指定した項目だけを保持し、省略項目は上位から継承する。endpointOverhangとendpointMarkersは補助Lineの描画だけに使用する。

各Sketchは`appearance`、各Geometryは`appearance`、Block Instanceは`appearanceOverride`を持つ。Block Definition内部のSketch／Geometryも同じ構造を持つ。

## 3. Geometry

Point、Line、Circle、Arcは従来の幾何情報に加えて`sketchId`と`appearance`を持つ。Line、Circle、Arcは`construction`を持つ。

Block Projectionは保存せず、DefinitionとInstanceから生成する。ProjectionのGeometryRefは`{ kind, path[] }`を正規形とし、保存文字列では`BI1@B2I1@L1`のようにpathを`@`で結合する。

## 4. Sketch

Sketchは`id`、`name`、`parentSketchId`、`kind`、`appearance`を持つ。ROOTは階層ルートであり、通常Geometryの作成先にはしない。

## 5. Block

Block Definitionはローカル座標のSketch、Geometry、Constraint、子Block Instanceに加え、Definition固有の`parameters[]`と`nextDimensionParameterIndex`を保持する。Block Instanceは配置`x`、`y`、`rotation`、固定状態、有効内部Sketch、`appearanceOverride`を保持する。

Appearance OverrideはInstance全体への一括Overrideであり、そのInstanceから展開されるすべてのProjection Geometryへ適用する。

## 6. Constraint Dimension表示

寸法を持つConstraintの`dimension`には配置情報と`display`を保存する。

```text
display
  visible
  precision       // nullは自動
  prefix
  suffix
  toleranceUpper  // nullはなし
  toleranceLower  // nullはなし
  arrows
  extensionLines
```

`toleranceUpper`と`toleranceLower`は既存JSONとの互換性のためデータモデルに保持するが、現在のProperties UIでは編集項目を表示しない。

すべての拘束寸法と参照寸法は`parameterName`を持つ。拘束寸法は正式な入力値として`expression`を保存し、その評価結果を既存の`target`へsolver用cacheとして反映する。参照寸法はGeometryから測定するため式を持たず、`target`を入力値として扱わない。別の注記寸法データは持たない。

Documentおよび各Block Definitionは次を持つ。

```text
parameters[]
  name
  expression
nextDimensionParameterIndex
```

`nextDimensionParameterIndex`は新規寸法名`d1`、`d2`、…の単調増加counterであり、削除済み番号を再利用しない。

## 7. Document Annotation

`annotations[]`に次を保存する。

- Leader: `id`、`visible`、`geometryRef`、`start`、`elbow`、`end`、`text`、`style`
- Free Text: `id`、`visible`、`x`、`y`、`text`、`style`

Leaderの`geometryRef`はGeometryの移動に追従するアンカーを解決する。参照Geometryを削除した場合は該当Leaderも削除する。

## 8. ID

通常Geometryは既存の`P`、`L`、`C`、`A`、Sketchは`S`、Block Definitionは`B`、Block Instanceは`BI`、Annotationは`AN`を接頭辞とする。読込時は既存IDから次の採番値を予約する。

## 9. 読込と互換性

Loaderは旧Geometry、Constraint、Sketch、Blockの不足fieldを補い、現行構造へ正規化する。version 9以前では名前空間ごとの寸法配列順に`d1`以降を付与し、既存拘束寸法の`target`を現在のUI単位による数値式へ変換する。参照寸法には名前だけを付与する。旧JSONに含まれる表示専用モード、Sheet、Sheet style、Sheet annotationは移行せず完全に破棄する。

version 10では各名前空間の識別子、重複、予約名、式の構文、未定義参照、循環参照、ゼロ除算、非有限値を検証する。不正な場合は問題のsymbolと理由を通知して読込全体を中止し、現在のDocumentを保持する。

保存→読込→保存で、現行fieldの意味とIDを維持する。`savedAt`以外の現行データは反復round-tripで安定する。

## 10. 履歴

Undo/Redoのsnapshotはversion 10と同等のDocument状態を保持し、Parameter、寸法名、式、評価cache、次の寸法採番値を含む。Block Editorのdraftとlocal履歴、clipboardにも対象scopeの同じ情報を保持する。Selection、hover、Interaction State、View State、viewportは永続Documentの一部ではない。
