# データモデルと永続化

## 1. Document JSON

保存ファイルの正式な拡張子は`.jot2d`とし、内容はversion 22のDocument JSONとする。拡張子の変更によってJSONのfieldや構造は変更しない。

```text
document
  version: 22
  documentName
  units
    length: "mm"
  parameters[]
  nextDimensionParameterIndex
  defaultAppearance
  defaultConstructionAppearance
  defaultDimensionAppearance
  sketches[]
  activeSketchId
  points[] / lines[] / circles[] / arcs[] / splines[]
  constraints[]
  blockDefinitions[]
  blockInstances[]
  geometryInstances[]
  annotations[]
  hatches[]
  referenceImages[]
  nextHatchIndex
  savedAt
```

表示モード、Sheet、active Sheetは保存しない。

Documentのモデル長さはmmへ固定する。Point座標、Circle／Arc半径、拘束寸法、Block Instanceの配置、Annotation位置、Hatch seed、Reference Imageのworld寸法など、モデル空間に属する長さはすべてmmとして保存・計算する。`units.length`は常に`"mm"`であり、単位変更によるGeometryの再解釈や拡大縮小は行わない。Dimension Appearance、AnnotationおよびHatchで画面上の大きさを指定する概算mmはモデル長さとは別の表示属性である。

File System Access APIで取得した現在のファイルハンドルはapplication sessionだけで保持する実行時状態であり、Document JSON、Block Editor draft、Clipboard、Undo/Redo履歴には含めない。

## 2. Appearance

Appearanceは次の部分オブジェクトである。

| field | 型 | 意味 |
| --- | --- | --- |
| `visible` | boolean | 通常表示で描画・hit対象にするか |
| `color` | CSS color string | 線・点の通常色 |
| `lineType` | `solid` / `dashed` / `dashdot` / `dashdotdot` / `dotted` | 実線／破線／一点鎖線／二点鎖線／点線 |
| `lineWidth` | number | 画面上の線幅 |
| `endpointOverhang` | boolean | 補助Lineを両端から延長して描画するか |
| `endpointMarkers` | boolean | 補助Lineの元の両端に点を描画するか |

`defaultAppearance`はvisible、color、lineType、lineWidthをすべて持つ。`defaultConstructionAppearance`は補助Geometryへ適用するDocument既定であり、visible、color、lineType、lineWidth、endpointOverhang、endpointMarkersをすべて持つ。これら3つのDocument fieldはDocument設定UIから編集し、各Sketchで未設定のfieldを解決する直接の継承元とする。`defaultConstructionAppearance`は`defaultAppearance`を継承せず、補助Geometryの各fieldを独立して解決する。旧JSONなどで`defaultConstructionAppearance`がない場合は、表示あり、`#64748b`、一点鎖線、1px、端部のはみ出しあり、端部の点ありとして補完する。endpointOverhangとendpointMarkersは補助Lineの描画だけに使用する。

Root以外の各Sketchは通常Geometry用の`appearance`、補助Geometry専用の部分上書き`constructionAppearance`、寸法専用の部分上書き`dimensionAppearance`を持つ。各fieldは親Sketchを経由せず、未設定なら対応するDocument既定を直接継承する。`constructionAppearance`は同じSketchの`appearance`も継承しない。Root Sketchの3つのfieldは空Objectとして保存し、表示解決や編集には使用しない。旧データのDocument Rootに保存された外観は読込時にDocument既定へ移し、Block DefinitionのRootに保存された外観は内部の各子Sketchへ移して表示を維持する。各Geometryは`appearance`、Block Instanceは`appearanceOverride`を持つ。Block Definition内部のSketchも同じDocument既定を基底とし、親子継承は行わない。

## 3. Geometry

Point、Line、Circle、Arcは従来の幾何情報に加えて`sketchId`と`appearance`を持つ。Line、Circle、Arcは`construction`を持つ。Line、Circle、ArcおよびSplineは、同じSketch内の共通重なり順を表す非負整数`drawingOrder`を持つ。

Splineは次を保持する。

```text
splines[]
  id
  definitionMode: "fit"
  degree: 3
  fitPoints[]       // 3個以上のPoint ID
  closed
  endCondition: "natural"
  construction
  sketchId
  drawingOrder
  appearance
```

Splineは3次・非有理・フィット点方式だけを扱う。開Splineはchord-length parameterによるnatural cubic補間、閉Splineは周期的cubic補間を使用する。fit pointは同じscope・同じSketchの通常Pointを参照し、隣接する同一点参照、3点未満、存在しないPointを含む現行JSONは不正とする。詳細は[スプライン](./10-スプライン.md)を参照する。

Block Projectionは保存せず、DefinitionとInstanceから生成する。ProjectionのGeometryRefは`{ kind, path[] }`を正規形とし、保存文字列では`BI1@B2I1@L1`のようにpathを`@`で結合する。

スケッチ投影、ミラー、直線パターンは`geometryInstances[]`へ保存し、表示Geometryを参照元から動的に生成する。生成Geometry自体は通常Geometry配列へ保存しない。GeometryRefは通常Geometry、Block Projection、派生Geometryを同じ`{ kind, path[] }`形式で参照する。詳細は[派生Geometryインスタンス](./12-スケッチ投影.md)を参照する。

## 4. Sketch

Sketchは`id`、`name`、`parentSketchId`、`kind`、`appearance`、`constructionAppearance`、`dimensionAppearance`を持つ。ROOTは階層ルートであり、通常Geometryの作成先にはしない。

## 5. Block

Block Definitionはローカル座標のSketch、Splineを含むGeometry、Constraint、Annotation、Hatch、編集用Reference Image、子Block Instance、派生Geometry Instanceに加え、Definition固有の`parameters[]`、`nextDimensionParameterIndex`、`nextHatchIndex`を保持する。Document直下と各Block Definitionはそれぞれ独立した`annotations[]`、`hatches[]`、`referenceImages[]`、`geometryInstances[]`を持つ。Definition内部のReference ImageはBlock Editorでだけ使用し、Block Instanceへ投影しない。Block Instanceは配置`x`、`y`、`rotation`、固定状態、有効内部Sketch、`appearanceOverride`、`drawingOrder`を保持する。派生Geometry Instanceも同じSketch内の共通重なり順を表す`drawingOrder`を持つ。Block Instanceと派生Geometry Instanceは、生成物ごとではなくInstance全体を1つの描画Objectとして扱う。

Appearance OverrideはInstance全体への一括Overrideであり、そのInstanceから展開されるすべてのProjection GeometryおよびProjection Annotationへ適用する。

## 6. Constraint Dimension Appearance

Documentは拘束寸法・参照寸法の既定値である`defaultDimensionAppearance`を持つ。所属Sketch自身の`dimensionAppearance`だけを適用し、その後に寸法ごとの部分上書きである`dimension.display`を適用する。既存JSONとの互換性のためfield名は`display`を維持するが、UIおよび仕様上はDimension Appearanceとして扱う。

```text
defaultDimensionAppearance / sketch.dimensionAppearance / dimension.display
  visible
  color           // #rrggbb
  lineWidth       // 画面上の線幅（px）
  precision       // nullは自動
  prefix
  suffix
  toleranceUpper  // nullはなし
  toleranceLower  // nullはなし
  terminatorType          // arrow / filledArrow / dot
  terminatorSize          // 矢印の長さまたは点の直径（mm）
  extensionLineOvershoot  // 寸法補助線の突出量（mm）
  extensionLineOriginGap  // 寸法補助線の起点すき間（mm）
  arrowheadAngle          // 矢印を構成する2辺の開き角（度）
  dimensionTextHeight     // 寸法文字の高さ（mm）
  dimensionTextGap        // 寸法文字領域と寸法線との間隔（mm）
```

`defaultDimensionAppearance`は全fieldを持つ。Sketchの`dimensionAppearance`と`dimension.display`は明示変更したfieldだけを持ち、省略fieldはそれぞれDocument既定または所属Sketchの実効値を継承する。寸法の個別Colorまたは線幅を空にすると上書きを削除し、所属Sketchで解決した値へ戻る。端末記号は左右共通で、標準矢印、塗りつぶし矢印、点から選択する。寸法補助線と端末記号は常時表示し、表示切替fieldは持たない。初期値は表示あり、`#64748b`、線幅1.2px、精度自動、空のPrefix／Suffix、標準矢印、突出量1.5mm、起点すき間1.5mm、端末サイズ4mm、開き角30°、文字高さ5mm、文字間隔0mmとする。旧JSONにSketchの`constructionAppearance`／`dimensionAppearance`がない場合は空の部分上書きとして読み込み、Document既定表示を維持する。

`toleranceUpper`と`toleranceLower`は既存JSONとの互換性のためデータモデルに保持するが、現在のProperties UIでは編集項目を表示しない。

すべての拘束寸法と参照寸法は`parameterName`を持つ。拘束寸法は正式な入力値として`expression`を保存し、その評価結果を既存の`target`へsolver用cacheとして反映する。version 17の`expression`でParameterまたは寸法symbolを参照する場合は`"width"`や`"d1"`のように識別子をダブルクオーテーションで括る。参照寸法はGeometryから測定するため式を持たず、`target`を入力値として扱わない。別の注記寸法データは持たない。

version 14の複数GeometryオフセットはConstraint型`offsetChainDimension`として保存する。`sources[]`は基準Line／ArcのGeometry IDと`reversed`を順序付きで持ち、`offsets[]`は対応する結果Geometry IDを同じ順序で持つ。さらに共通距離`target`、左右を示す`side`、`closed`、固定値`joinType: "miter"`、寸法表示対象の`dimensionSegmentIndex`、通常の寸法fieldを保持する。基準と結果は2要素以上かつ同数・同種でなければならず、不正な現行データは読込を拒否する。version 13以前にはこの型が存在しないため追加の移行は行わない。

Documentおよび各Block Definitionは次を持つ。

```text
parameters[]
  name
  expression
nextDimensionParameterIndex
```

`nextDimensionParameterIndex`は新規寸法名`d1`、`d2`、…の単調増加counterであり、削除済み番号を再利用しない。

## 7. Annotation

`annotations[]`に次を保存する。

- Leader: `id`、`sketchId`、`visible`、`geometryRef`、`start`、`elbow`、`end`、`x`、`y`、`rotation`、`text`、`style`
- Free Text: `id`、`sketchId`、`visible`、`x`、`y`、`rotation`、`text`、`style`

すべてのAnnotationはRoot以外の作図可能Sketchに所属する。Leaderの`geometryRef`は同じ所属Sketch内のGeometryまたは、そのSketchに配置されたBlock Projectionを参照し、Geometryの移動に追従するアンカーを解決する。参照Geometryを削除した場合は該当Leaderも削除する。Annotationの`style`はcolor、概算mmの`textHeight`、fontFamily、bold、italic、textAlignを完全値で保持し、Leaderではさらに画面pxのlineWidth、`solid`／`dashed`／`dashdot`／`dashdotdot`／`dotted`のlineType、terminatorType、概算mmのterminatorSizeを保持する。Sketch一般Appearanceは継承せず、Sketchから受けるのは表示状態だけである。旧`style.fontSize`は読込時に`fontSize / (96 / 25.4)`で`textHeight`へ変換し、保存時は`fontSize`を出力しない。

Block Projection Annotationは保存せずDefinitionとInstanceから導出する。IDは`BI1/AN1`、入れ子では`BI1/BI2/AN1`のように最上位Instanceからのpathを`/`で連結する。座標、Leader折線、文字位置、回転、GeometryRefはInstance変換を合成し、投影先Sketchは最上位Instanceの配置Sketchとする。

## 8. Hatch

`hatches[]`は`id`、`sketchId`、同じSketch内の共通重なり順`drawingOrder`、作成位置`seed`、外周と穴の`boundaryLoops`、完全値の`appearance`を持つ。境界spanは座標copyではなく、Line／Circle／Arc／SplineのGeometryRef、端点または交差相手と交点順、進行方向、完全Circle／閉Spline区分を保存する。Appearanceはvisible、`parallel`／`cross`／`solid`のpatternType、angle、画面mm表記のspacing、color、画面pxのlineWidth、0～1のopacityから成り、Document／Sketch Appearanceを継承しない。`solid`ではcolorとopacityを面の塗りへ使用し、angle、spacing、lineWidthは保存するが描画には使用しない。詳細は[ハッチング](./09-ハッチング.md)を参照する。

## 9. Reference Image

`referenceImages[]`は`id`、`name`、`sketchId`、MIME、Base64 Data URL、pixel幅・高さ、mm座標上の中心`x`／`y`、pixel当たりの正のmm長さ`scale`、radianの`rotation`、0～1の`opacity`、`visible`、`locked`を持つ。MIMEはPNG、JPEG、WebPだけとし、長辺は3000px以下、scaleは縦横共通とする。画像はConstraint、solver、snap、Hatch境界、Block Projectionへ参加しない。詳細は[参照画像](./11-参照画像.md)を参照する。

## 10. ID

通常Geometryは既存の`P`、`L`、`C`、`A`に加えてSplineの`SP`、Sketchは`S`、Block Definitionは`B`、Block Instanceは`BI`、スケッチ投影Instanceは`SPI`、ミラーInstanceは`MI`、パターンInstanceは`PI`、Annotationは`AN`、Hatchは`H`、Reference Imageは`IMG`を接頭辞とする。`nextHatchIndex`は削除済みHatch番号を再利用しないための単調増加counterである。読込時は既存IDと保存済みcounterから次の採番値を予約する。

## 11. 読込と互換性

Loaderは旧Geometry、Constraint、Sketch、Blockの不足fieldを補い、現行構造へ正規化する。version 19以前は`units: { length: "mm" }`を補完し、保存済みのモデル数値を変換せずmmとして扱う。version 20以降では`units`の欠落、または`length`が`"mm"`以外のDocumentを拒否する。version 11以前のDimension Appearance長さ値は画面pxとして読み、`mm = px × 25.4 / 96`でversion 12のmm値へ変換する。旧`arrowheadLength`は`terminatorSize`へ移し、旧`arrows`と`extensionLines`は破棄する。version 10以前のLeaderは解決できる参照GeometryのSketchへ、Free Textは保存時のactive Sketchへ割り当てる。Rootまたは参照不能の場合は最初の作図可能Sketchを使用する。Block Definition内も同様に、Leaderは参照先Sketch、Free TextはDefinitionのactive Sketchへ移行する。version 9以前ではさらに名前空間ごとの寸法配列順に`d1`以降を付与し、既存拘束寸法の`target`をmmの数値式へ変換する。参照寸法には名前だけを付与する。旧JSONに含まれる表示専用モード、Sheet、Sheet style、Sheet annotationは移行せず完全に破棄する。

version 22ではDocument直下と各Block DefinitionのLine、Circle、Arc、Spline、Hatch、Block Instance、派生Geometry Instanceへ`drawingOrder`を保存する。順序は同じSketch内だけで比較し、0から始まる連続した非負整数へ正規化する。version 21以前またはfieldがない旧データでは、従来の表示を維持するためHatchを背面、その上へLine、Circle、Arc、Spline、Block Instance、派生Geometry Instanceの配列順で並べる。一部だけに有効な順序がある場合はその相対順を保ち、不足するHatchを背面、その他のObjectを前面へ補う。

version 21ではDocument直下と各Block Definitionの`geometryInstances[]`を必須とし、種類、所属Sketch、GeometryRef、ミラー軸、パターン方向・間隔・コピー数を検証する。version 19／20の`sketchProjection` Constraintは1拘束につき1個のスケッチ投影Instanceへ移行し、旧投影先の通常Geometryを通常配列から除く。旧IDを`legacyOutput`として維持するため、既存のConstraint、Leader、Hatch参照は変えない。version 18以前は`sketchProjection`を持たないものとして扱う。version 18で追加したDocument直下と各Block Definitionの`referenceImages[]`検証、およびversion 17以前の空配列移行を維持する。version 17以降は各名前空間の識別子、重複、予約名、式の構文、参照識別子のダブルクオーテーション、未定義参照、循環参照、ゼロ除算、非有限値を検証する。version 16以前の式は引用されていない識別子をダブルクオーテーションで括る形式へ移行してから検証する。Document直下と各Block Definitionでは`splines[]`を必須配列とし、SplineのID、固定されたdefinition mode・degree・end condition、所属Sketch、fit point参照、開閉、construction、Appearanceを検証する。version 14以前はSplineなしとして移行する。加えて、各Annotationの`sketchId`が同じscopeのRoot以外のSketchを指すこと、Leaderの参照先が同じ所属Sketchにあること、DocumentおよびBlock DefinitionのHatch配列・採番値・所属・境界記述・Appearance構造、および`offsetChainDimension`の順序付き参照構造を検証する。HatchのpatternTypeは`parallel`、`cross`、`solid`だけを受理する。Hatchの境界Geometry欠落は保存可能な無効状態として許容する。中心線拘束は`parallelLinesCenterline`または`pointPairCenterline`だけを受理し、旧`pointOnLineMidpoint`はversion 15以前の読込時に破棄してPoint座標を維持する。version 16以降に旧型が含まれる場合は不正な現行JSONとして読込を拒否する。不正な場合は問題のsymbolまたはObjectと理由を通知して読込全体を中止し、現在のDocumentを保持する。version 12以前はHatchなしとして移行する。

保存→読込→保存で、現行fieldの意味とIDを維持する。`savedAt`以外の現行データは反復round-tripで安定する。

## 12. 履歴

Undo/Redoのsnapshotはversion 22と同等のDocument状態を保持し、Document単位、共通描画順、派生Geometry Instance、Splineとfit point、中心線拘束、Parameter、寸法名、引用形式の式、評価cache、次の寸法採番値、順序付きチェーンオフセット参照、Sketchごとの3種のAppearance、寸法の個別Appearance、Annotationの所属とstyle、Hatchと次のHatch採番値、Base64埋め込みのReference Imageを含む。Block Editorのdraftとlocal履歴にも対象scopeの同じ情報を保持する。Reference Imageはclipboardへ含めない。Selection、hover、Interaction State、View State、viewport、Sketch Tree分類の開閉状態、Sketch Tree幅は永続Documentの一部ではない。
