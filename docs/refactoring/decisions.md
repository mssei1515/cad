# 判断事項と未解決事項

現在の規則は正式仕様を参照する。過去の調査経緯はGit履歴に保持する。

## 承認済みの方針

- 依存先のsolve失敗は操作ごとに扱う。ドラッグ・Parameter適用の全体復元と、通常のDefinition編集で参照元を維持する違いを保持する。[編集と履歴](../../spec/contracts/編集と履歴.md)のTX-01～05に従う。
- Block外観は配置先Sketchを含む現行の解決順を維持する。[外観](../../spec/contracts/外観.md)のAPP-03に従う。
- 読込全体の拒否、無効参照拘束の保持、復元不能なBlock内部拘束の解除を区別する。[読込と互換性](../../spec/data/読込と互換性.md)のLOAD-01～05に従う。
- 不要な移動案内と移行資料は削除する。正式仕様と、進行中の作業に必要な資料を残す。

## 優先する調査

| 対象 | 現状と次の確認 |
| --- | --- |
| 拘束選択エラー | 共通E2E fixtureがundefinedのid／center読取りエラーを除外している。対象指定途中の再現、原因修正、除外の撤去を行う |
| 実際の不具合・性能 | ユーザーが経験した図面・操作は未特定。既存fixtureの残差・追従量・計算時間と比較する |
| 保存往復 | 角度寸法の未使用linear offsetのnull／0差がexpected failureとして残る |
| 取消と履歴 | 線作成開始の取消で履歴が余分に残るexpected failureがある |
| 保証の不足 | 混在削除、全version・不正field、参照・入れ子外観の全組合せは未網羅 |

保証の正本は[保証対応](../../spec/verification/保証対応.md)。既知の失敗を通常の成功へ算入しない。

## 実装・テストを分離するときの注意

Selection・hover・viewportは履歴対象外だが、失敗後の無効なSelectionを許容する意味ではない。pointercancel・Esc・Sketch切替も同じ取消として統合する前に個別に照合する。

拘束残差・参照検証の組合せは下位テストへ集約し、UIの代表経路はE2Eに残す。サーバー起動の共通化前にはportと環境設定の違いを調べる。性能の合格閾値は測定前に変更しない。
