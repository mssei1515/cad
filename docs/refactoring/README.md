### R3の測定結果

Windows x64、Node v24.11.1、Playwright Chromium revision 1223、1 worker。responsive Line fixtureを操作ごとに初期化し、Geometry／寸法／Panそれぞれ240件のpointermoveを同一task内で送信する。次のrAFで最新位置を1回反映し、その後pointerupで確定する。[検証方法](../../spec/verification/検証方法.md#5-ドラッグの処理別測定)に再実行手順を記載。

| 寸法確定処理 | 変更前 | 変更後 |
| --- | --- | --- |
| 3回の同期実行時間 | 23.3／19.9／19.9ms | 18.1／19.9／24.9ms |
| 拘束解析 | 1回 | 0回 |
| Sketch Tree全再生成 | 1回（内訳追加後の追測で確認） | 0回 |
| Geometry読出しの実生成 | 8回 | 5回 |
| 描画／履歴記録 | 各1回 | 各1回 |

角度以外の寸法は表示配置だけを変更するため、確定後に選択UIと寸法入力だけを更新する。角度寸法はtarget変更を伴うため従来の全体更新を維持する。形状・拘束値不変、Properties表示、Undo／Redo往復を既存E2Eに追加した。

処理回数の削減は確認できたが、時間の範囲は重なっており有意な高速化とは扱わない。追加内訳測定ではProperties再生成が寸法確定の17.7ms中16.7msを占めた。PropertiesのDOM再生成・式入力highlightの内訳は[UI差分更新](./backlog.md#ui差分更新)の残課題とする。Geometryのsolve手順・精度・追従条件は変更していない。計測点追加中の比較であり、browser描画完了時間や実図面での遅延解消を示すものではない。

## 各作業の進め方

1. 対象IDを「作業中」にし、関連仕様・実装・テストを確認する。
2. 1つの責務を小さな差分で変更する。新しい挙動や復元範囲の判断が必要になった場合は、選択肢と影響を示してユーザーへ確認する。確認が必要な部分だけを「確認待ち」にする。
3. 関連する既存テストを必ず実行する。状態を変える経路では成功・失敗・取消後のDocument、参照、Undo／Redoを確認する。計算やドラッグに影響する変更では、同じfixture・環境で精度と性能も比較する。
4. specとの一致、不要な旧経路、デバッグ出力、関係のない差分を確認してCommit・Pushする。進捗表と現在地を同じ作業の中で更新する。
5. 段階の終了時に全体検証を行い、結果とcommitを記録する。developへ統合後、統合済みの作業ブランチを削除し、次段階は新しいブランチで開始する。

「完了」は成果物・必要な検証・Commit・Pushが揃った状態とする。段階の完了にはdevelopへの統合も含む。検証未実施・失敗・確認待ちを完了へ含めない。予定を変更するときは対象と理由を更新し、日々の詳細ログを別文書に増やさない。
