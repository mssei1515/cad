# 仕様整理と段階的リファクタリング

このディレクトリは検討資料であり、正式仕様ではない。現行仕様は [spec/README.md](../../spec/README.md) を参照する。未決定の案を実装上の根拠として使用しない。

## 今回の範囲

仕様全体の章構成を棚卸しし、拘束・ドラッグ・履歴を中心に仕様、実装経路、既存テストを照合した。全機能の実装一致、拘束エラーの原因、ドラッグ性能を検証済みという意味ではない。

- [新構成と移行台帳](./spec-inventory.md): 現行の各章を残したまま移動先の候補を管理する。
- [共通契約の草案](./contracts.md): 編集権限、操作の確定、失敗、履歴を適用範囲付きで整理する。
- [整理候補と判断事項](./decisions.md): 重複、仕様の不整合、削除候補、テスト整理を記録する。

## 新しい仕様の目次案

| 領域 | 内容 | 読む目的 |
| --- | --- | --- |
| 基本概念 | Document、Sketch、Geometry、Constraint、Parameter、表示Objectの役割 | モデル全体を理解する |
| 共通契約 | 所属と参照、編集可否、操作の確定と復元、履歴、表示の優先順位 | 複数機能で守る条件を確認する |
| 機能別操作 | 作図、拘束入力、ドラッグ、削除、コピー、Block、派生Instance、注記等 | 対象・操作・結果・例外を確認する |
| UI | レイアウト、入力方法、選択、コマンド状態、言語、テーマ | 操作と表示の仕様を確認する |
| データと互換性 | 現行schema、ID、参照、保存、旧版の移行と拒否条件 | 保存済み図面を安全に扱う |
| 計算契約 | 幾何計算、残差、収束、受入れ判定、縮退、依存順序 | 計算の正しさと境界条件を確認する |
| 検証対応 | 契約とテストの対応、実行方法、未保証項目 | 変更による影響を検証する |

実際の関数配置・分割手順・改善予定は開発資料へ置く。現行の互換性規則は古いversionに関するものでも現行仕様として保持する。

## 記述の形

機能ごとに必要な項目だけを記載する。空欄を埋めるために仕様を増やさない。

1. 対象と前提条件
2. 入力・操作
3. 成功時の結果
4. 取消・失敗時の結果と復元範囲
5. 履歴・永続化
6. 共通契約への参照と固有の例外
7. 対応する検証

共通ルールの本文は一か所へ置く。概要からはリンクし、数値や条件を再掲しない。ルールには変更後も追跡できるIDを付け、テストはIDと保証内容を対応させる。草案のIDは正式仕様へ採用した時点で固定する。

## 段階と終了条件

| 段階 | 作業 | 次へ進む条件 |
| --- | --- | --- |
| 1. 棚卸し | 章の移行台帳、共通契約草案、判断事項を作る | 現行と提案、確認済みと未確認が区別されている |
| 2. 仕様整理 | 拘束・ドラッグ・履歴の重複を集約し、差異の適用範囲を確定する | 各旧項目に移動先または承認された削除理由がある |
| 3. 検証基盤 | 再現図面、操作、期待結果、現状の性能を記録する | 不具合を正常系の基準へ固定せず、同じ条件で比較できる |
| 4. 実装分離 | 操作の確定／復元、solve呼出し、依存更新の責任を順に分ける | 対象領域の仕様・回帰テスト・性能比較が一致する |
| 5. 横展開 | 表示、保存、その他の機能へ適用する | 同じ重複を再導入しない構造になっている |

段階2と3は同じ領域で並行できる。全仕様の完成を待って一括で書き直さない。E2Eの削減と実装の大幅変更は同時に行わず、移した保証が新しいテストで成立してから旧テストを除く。

## 今回の確認記録

基準コードは `e85f24e`。作業開始時のtracked変更はなし。mainとdevelopは同じ内容だったが、developにリリースmerge commitが未反映だったためfast-forwardで同期した。

構文チェックと単体テスト68件は成功。関連E2Eは空Document起動、固定矩形の代表targetドラッグ、Parameter非収束時の復元、参照依存順と範囲外参照無効化の4件を実行し、すべて成功した。E2E共通fixtureに既存の例外除外があるため、これを全操作の例外不在の証明とはしない。

正式仕様の03ではドラッグ・solveの長文を段階と条件で構造化し、07では起動sampleという誤記とfixture固有IDへの言及を修正した。挙動、数値閾値、保存互換性は変更していない。性能測定とE2E全件の実行はこの棚卸しの実施範囲に含めない。

ユーザー確認により操作別の復元範囲の違いを維持する方針が確定した。共通規則を[13-編集の確定と失敗](../../spec/13-編集の確定と失敗.md)へ正式化し、03・05・08から参照する。Parameter評価の手順は08を正とし、03の再掲を除いた。残りの草案と棚卸しは未採用部分を含む。

正式化に合わせ、Block拘束追加失敗時の復元、Block Editorの独立履歴、Block Parameter適用のE2Eを追加実行し、3件とも成功した。今回の関連E2Eは合計7件。非ParameterのDefinition更新が外部拘束を壊した場合など、操作別失敗の全組合せを保証する検証は今後の対象として残る。

続く読込・Splineの整理では、02へLOAD-01～05、検証条件、旧版移行表を集約し、01・03・04・10の重複と誤記を整理した。Splineの不正読込時のDocument全体保持と、Hatchの境界欠落状態の保存・再読込の検証を強化し、関連E2E17件が成功した。詳細は[照合結果](./decisions.md)を参照する。
