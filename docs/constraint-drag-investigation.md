# 拘束表示とドラッグの調査

## 対象と再現方法

比較元は develop の `284b137e55631310e23c9b6d63710520d7175793`。提供された元ファイルは変更せず、取込時点の形状・拘束を tests/fixtures に保存した。画像と保存日時を除き、図形、寸法、Sketch 階層を保持している。調査中に元データが更新されても、回帰テストでは保存済みの同一スナップショットを使う。

| 報告 | fixture | 検証対象 |
| --- | --- | --- |
| 1.jot2d | collapsed-fillets.json | 全4線、各3か所 |
| 2.jot2d | tangent-offset-chain.json | 8線、7円弧の本体と両端、4点 |
| 飛行機.jot2d | aircraft-tangent-arcs.json | Sketch-1-1 の A2・A3、各3か所 |
| 3.jot2d | coupled-line-drag.json | 全15線、L2 は3か所と連続左右往復 |
| 4.jot2d | coupled-horizontal-line-drag.json | L27、3か所と連続上下往復 |
| 5.jot2d | coupled-vertical-line-drag.json | L6、3か所と連続左右往復 |

単発の大きな移動だけでは 3 の停止を再現できなかった。「左右でも遅い・固まる」という情報を受けて細かい入力を往復させ、別の図形が徐々に変形し、自由度が減って停止する経路を確認した。このため、到達座標だけでなく途中位置の残差・自由度・全図形の状態色も比較する。

## 事例から共通原因へ

### 接点の式と表示補正

1 の極小フィレット、2 の接する円弧とオフセットでは、正しい接点で距離残差の一次微分が消える。一方、僅かに接点を外れると小さな微分が現れる。独立した拘束として数えると同じ拘束のまま黒とオレンジが変わり、逆に微分がゼロだと実在しない自由度が現れる。

明示された一致・点上・接線の組合せから接点が一意に決まる場合に限り、接点方向の式で正則化した。オフセット先にも接点関係を引き継ぐが、元の接続位置の残差も残し、接続不能な形状を成功扱いしない。同心・同半径の内接は接点方向が一意でないため、方向固定の対象から除外する。近接だけの円弧や、無効にした接線拘束は対象にしない。

短い円弧を表示上の都合で全円へ変換する処理が、拘束された端点を上書きしていた。読込順序と補正条件を修正し、端点一致・固定・オフセット拘束が参照する角度を保つ。

### 数値の単位と丸め誤差

半径約6600の円弧と下限付近のフィレットでは、同じ角度変化が表す距離が異なる。角度に累積した周回数が数値微分の刻みまで拡大させる問題もあった。角度を半径に応じた移動距離へ換算し、自由度解析と反復補正の尺度をそろえた。中央差分の外挿、実際の差分区間、周回数に依存しない角度刻みを使用する。角度正規化は繰返し減算から剰余へ変更した。直線対称の式も、反射後の大きな座標同士を引く代わりに相対ベクトルを使う。

L27 の連続往復では特定位置だけ自由度が3から2になった。保存したヤコビアンを独立に特異値分解した結果、該当特異値は約2.75e-9で、微分誤差の増幅と確認できた。高次差分に適した角度刻みへ変更すると、この経路でも自由度が安定した。色だけを固定したり、判定履歴で変動を隠したりする処理は追加していない。

解析では近傍の拘束面に一時補正し、同じ位置で線の法線も求め、その後モデル座標を復元する。解析した法線と未補正の法線を混ぜると、L9 の支持位置拘束が未拘束へ変わることも確認し、両者を一致させた。

### 可動方向とドラッグ目標

飛行機 A3 では半径だけを目標にすると、連動する中心移動によって円周がマウスから離れた。円周そのものとマウスの距離を目標にし、円弧端点でも中心と半径の連動を含めた。

L2・L27・L6 では補正の累積が無関係な自由度まで変形させ、特異姿勢へ近づいた。線はドラッグ開始形状を基準に各目標を解く。左右移動で縦座標まで追加固定するなど、拘束維持に必要な伸縮を妨げる目標は作らない。

この変更を回転できる既存の L8・L15・L19 にも適用すると、端点移動が増幅する回帰が見つかった。向きと平行移動の可動性を解析し、自由な平行移動ができない線では投影後の座標を目標とする。回転によって開始時の線形近似から外れる場合は、直前の有効な位置から補正を継続する。判断は図形IDやファイル名ではなく拘束の自由度に基づく。

既存 P44 の高速・低速比較では、予測が半径下限を越えるだけで、まだ動ける半径を固定していた。下限前に補助変数を保持する場合は、ドラッグ対象に見える可動方向を失わないことを確認する。これにより、1 の小さな補助円弧の安定性と、P44 の到達可能な移動の両方を維持する。長い分岐拘束の点と線、A18 の円周ではマウスが到達可能範囲を越えることもある。拘束を維持して近づく補正を採用し、改善しなければ直前位置を保つ。

### 計算量と収束の問題

比較元の飛行機 A2 では1回の更新に最大約6.1秒を要する再現があった。1 の各線でも約100msの更新が見られた。これは移動量が減る問題とは別に計測した。

ヤコビアンは関係する拘束だけを評価し、減衰付き最小二乗は疎な積と Cholesky 分解を使用する。条件が悪い場合は QR 分解へ戻す。冗長拘束判定の直交化もゼロでない成分だけを処理する。途中で発生した長穴追加の遅延は密な直交化が原因だった。修正後の個別再検証では23操作の最大167msとなり、既存の350ms上限を満たした。

## 再発防止の検証

`tests/e2e/constraint-drag-regressions.spec.js` は8方向、遅い操作と速い操作、3回の往復、複数の掴む位置を検証する。L2・L27・L6 は各483サンプルの連続往復も実行する。計算経路の総preview数は24,537。途中・確定後のモデル残差は1e-4以下を要求し、報告された可動軸では追従誤差も確認する。

通常のファイル取込から実際のマウスイベントを送る7ケースでは、意図した図形IDの選択、往復中の自由度と色、Undo／Redo、保存データの再読込を確認する。スクリーンショットで選択線・円弧とPropertiesのIDも確認した。

単体テストでは半径・周回数・微小摂動・変数順序・拘束順序を変え、明示接点、非有限値、下限、オフセット、動的参照を検証する。接線削除で自由度が戻ること、同心同半径の内接、接続不能なオフセットも含む。既存の作図・拘束追加・点・線・円・円弧・端点・分岐拘束・派生Instanceのテストも併せて実行する。

再実行:

```powershell
npm run test:all
npx playwright test tests/e2e/constraint-drag-regressions.spec.js
```

## 測定の範囲

時間はこの端末のChromiumでの実測であり、任意の端末や図面で一定のフレームレートを保証するものではない。画像を除いたfixtureは拘束計算を再現するためのもので、画像描画やクラウドドライブの読込時間は測定対象外。オレンジは少なくとも一方向に自由度があることを示し、全方向へ自由に動ける意味ではない。実際の可動範囲を越えた場合と、解けるはずの移動が止まる不具合を区別して検証する。
